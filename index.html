Players

Each player works through modules 1–53 in order, staying on each for a random stretch of time, waiting if they get too far ahead of the slowest player, and waiting on 53 until everyone arrives. All of these settings apply while the piece plays.

Permutation

A permutation re-rolls each module's [a, b].choose repeat count, then the knobs push it further from the score. The knobs take effect on the next New permutation (or seed); they don't change the modules on their own. The same seed always gives the same permutation.

Audition

A utility for comparing SynthDefs: hear one module played by each, outside the piece, at the current tempo and that module's octave. Each card measures its SynthDef's peak level as it plays. Clicking a phrase in the module list picks that module here.

How this works. The score is read straight from the SuperCollider file when the page loads: every Pbind, plus either the player rules of Riley mode (Tett_A_In_C_2026.scd) or the Ptpar timeline of the 2019 arrangement (Tett_A_In_C.scd). The SynthDefs are compiled from the 2026 file into .scsyndef files and run on SuperSonic, which is SuperCollider's own synthesis server compiled to WebAssembly. Nothing is streamed: every sound is synthesized on this computer.

For a screen share, tick Share sound in Zoom so the class can hear it. SynthDefs: pluck after John Drumheller's Karplus-Strong example; star from sccode.org/1-522. Visuals in p5.js.
